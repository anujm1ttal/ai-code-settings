# Skill Abstract: Receiving Code Review (L0)

**Purpose**: Disciplined ingestion of review feedback — verify claims against the codebase before implementing, push back with evidence, never perform agreement.

**Core Logic**:
- **Iron Law**: Feedback is evaluated against the codebase, not obeyed or performed at.
- **Sequence**: READ all → UNDERSTAND (restate) → VERIFY against code → EVALUATE soundness → RESPOND (terse ack or evidenced pushback) → IMPLEMENT one item at a time via TDD.
- **Ambiguity rule**: If any item is unclear, clarify ALL unclear items before implementing ANY.
- **External feedback**: Suggestions to evaluate, not orders; YAGNI-grep before adding requested-but-unused features.

**Constraint**: "You're absolutely right!" and all performative agreement is banned — corrected code is the acknowledgment.
